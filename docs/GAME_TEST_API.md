# Python GameTest API

The test API follows Warforge's workflow: Python `test_*` functions drive a fresh,
seeded native world and advance exact fixed ticks with `st.step(n)`. Tests call
the actual C++ `Game::update`; there is no second simulation in Python. A small
JSON-lines bridge replaces Warforge's embedded Python dependency so logic tests
need only Python's standard library and the C++ test executable.

## Run tests

Build the project normally. `snake_game_test` is a headless executable: it does
not initialize raylib, an audio device, or a GPU context.

```powershell
./snake.ps1 gametest --list
./snake.ps1 gametest --tier logic
./snake.ps1 gametest --tier hunt
./snake.ps1 gametest --tier visual --native
./snake.ps1 gametest --tier bench
```

The Windows wrapper builds missing executables and locates an existing Python
runtime, including Blender's bundled Python. Pass `-Python PATH` or set
`SNAKE_PYTHON` to choose one. Rebuild after source changes with
`./snake.ps1 build`. The portable runner accepts the same test selection flags:

```powershell
python -m game_tests.run --list
python -m game_tests.run --single api_surface
python -m game_tests.run --single test_weapon_parity --repeat 3
python -m game_tests.run --single api_surface::test_seeded_control_is_reproducible
```

The runner accepts comma-separated exact module or `module::test_name`
selectors. Unknown selectors and empty selections fail. Each test begins with a
new seed, empty actors/equipment, disabled spawning, a stationary player, and
player immunity. Settings, entity handles, event totals, and fixture state reset
between tests. Tests can enable normal movement, spawning, and damage explicitly.

The default selection runs the `logic` tier. Use `--tier visual --native` for
native captures, `--tier hunt` for seeded stateful bug hunts, and `--tier bench`
for native update benchmarks. Comma-separated tiers and `--all` are supported;
visual tests require the native host and skip on a headless host. Modules declare
their tier with `TIER = "logic"`, `"visual"`, `"hunt"`, or `"bench"`.
Functions have a default budget of 600 simulation ticks;
longer scenarios set `test_function.timeout_ticks = 2400` (or the required exact
budget). Explicit resets within a test do not erase that test's consumed budget.

Every run writes a structured `result.json` under `artifacts/runs`, or at the
path passed with `--json`. Results contain each selected test, repetition,
status, tick usage, duration, and failure traceback. Test code lives outside the
shipping game's startup path.

Set `SNAKE_GAME_TEST_EXE` to use a different headless binary, or `SNAKE_NATIVE_EXE`
for the graphical binary. The runner also accepts `--exe PATH` and `--data PATH`.
`--native` runs the real hidden raylib game with `--test-api`, enabling captures.
Python 3.10 or later is sufficient; no pip dependencies are required.

Native `capture` accepts `render_alpha=0..1` to sample presentation between the
last two fixed updates. Omitting it renders the exact raw fixture pose. The
returned `reward_open` flag reports whether a boss reward reveal is visible.
These options help test display cadence and loot UI without changing simulation.

For the chest lottery, `capture(path, world_only=False, reward_time=1.2)` samples
the reel at an explicit time in seconds (`0..30`). It does not advance the UI
clock, grant/acknowledge a reward, or consume simulation RNG. At `0` the chest
is opening, `3.0` is mid-spin, and `6.7` shows the final reward. The returned
`reward_time` and `reward_revealed` describe that sample. Without `reward_time`,
captures use the current UI clock; simulation-only `step` does not advance it.

For a player killed by the simulation, `capture(path, death_time=0.3)` samples
the death dissolve without advancing combat or the presentation clock.
`death_time` accepts finite seconds in `[0,2]`; the player disappears at 0.72 s
and the results panel appears at 0.8 s when `world_only=False`. Enemy and summon
death poses use fixed simulation time and appear in `counts.snake_deaths`.

CTest registers the logic tier if CMake finds Python 3.10+. Pass
`-DSNAKE_PYTHON_EXECUTABLE=C:/path/to/python.exe` when configuring to choose an
interpreter. A headless-only build uses `-DSNAKE_BUILD_GAME=OFF`; pass its binary
with `--exe build-tests/bin/snake_game_test.exe` when running Python directly.

The `test_weapon_parity` module compares all 18 native variants with
[`fixtures/javascript_weapon_oracle.json`](../game_tests/fixtures/javascript_weapon_oracle.json),
generated by executing the original JavaScript classes, getters, and constants
at commit `b6cb72e66eebc1291d57efe63ebbe93ec602e863` using
[`reference_probe.mjs`](../game_tests/reference_probe.mjs). Live actor assertions
cover behavior separately from scalar formulas. The intended source contracts
and grid-safe fixes are described in [`WEAPON_PARITY.md`](WEAPON_PARITY.md).

The default logic tier also includes `test_weapon_functionality` (every base
rank, every evolution, real damage/kills/rewards, and out-of-range controls),
`test_evolution_functionality` (all nine actual boss-to-chest evolution paths
and their prerequisites), and `test_weapon_interactions` (naturally cast
secondary effects). Their catalog completeness gate fails if a shipped weapon
has no explicit live test. See [`WEAPON_TEST_COVERAGE.md`](WEAPON_TEST_COVERAGE.md)
for the per-weapon map and executed results. With `SNAKE_RUN_NATIVE_TESTS=ON`,
CTest additionally runs these modules through the hidden raylib game as
`snake_python_native_weapons`.

## Write a test

```python
from game_tests import snake_test as st


def test_nest_hatches_actual_snakes():
    st.equip("snake_nest", rank=1)
    target = st.spawn_enemy(864, 800, hp=100000, speed=0)
    st.step(1)
    state = st.snapshot()
    assert state["counts"]["nest_eggs"] == 1, state
    assert state["counts"]["mini_snakes"] == 0, state
    st.step(90)
    state = st.snapshot()
    assert state["counts"]["mini_snakes"] > 0, state
    assert st.enemy(target)["hp"] < 100000, state
```

Standalone scripts can use a session explicitly:

```python
from game_tests.snake_test import Game

with Game() as game:
    game.configure(freeze_player=False)
    game.step(120, direction=(0, -1))
    print(game.snapshot())
```

Coordinates use simulation units: a grid cell is eight units, the arena is
1,600 units wide, and the default player is at `[800, 800]`. Fixture placement
snaps to legal grid cells. `st.EAST`, `SOUTH`, `WEST`, and `NORTH` are cardinal
input vectors. `step(1)` advances exactly `1/60` second in a playing world;
paused/dead/victorious worlds retain their simulation state.

## Main methods

| Method | Purpose |
|---|---|
| `reset(seed=..., character=0, isolated=True)` | Rebuild a deterministic fresh world; use `isolated=False` for a normal run. |
| `configure(director=False, freeze_player=True, invulnerable=True, auto_choose=True)` | Set explicit fixture controls. `director` also controls scheduled grey spawning unless `grey_snakes` is supplied. Immunity prevents enemy contact damage and holds self-bites without starting collision grace, as in JavaScript. Arena walls and grey barriers still start lethal grace. Disabling immunity clears fixture protection. |
| `configure(elapsed=..., boss_clock=..., spawn_clock=...)` | Set a precise director/time fixture. |
| `configure(grey_snakes=True, grey_clock=89.96, grey_next_spawn=90)` | Enable scheduled grey heads independently of enemy spawning. Setting `elapsed` also sets the grey clock unless `grey_clock` is supplied. Disabling scheduled spawning leaves existing trails/heads intact. |
| `player(**fields)` | Set position, direction, length, HP, movement timer, or authored segment history. With no fields, inspect the player. |
| `equip(id, rank=1, evolved=False, cooldown=0)` | Equip/update a weapon or passive, observing equipment slot and rank limits. Returns its native resolved weapon specification. |
| `unequip(id)` | Remove equipment without deleting already-created effects. |
| `spawn_enemy(x, y, hp=1000, speed=0, kind="red")` | Create a target and return its stable handle. |
| `spawn_enemies(list_of_dicts)` | Create a bounded batch in one bridge call. |
| `spawn_grey_snake(path, alive=True, **fields)` | Create an oldest-first cardinal grey path of 1–168 points, strictly inside the boundary row/column. Supports `direction`, `previous`, `target`, `wall_direction`, `wall`, `wall_ticks`, `age`, and `move_clock`. At most one living head and thirteen total trails; other trails require a one-cell gap. Validation is atomic. |
| `spawn_pickup(x=None, y=None, kind="experience", value=1)` | Place a grid-snapped experience, heart, or chest fixture. Chest quantities are bounded to 1–100. |
| `set_enemy(handle, **fields)` | Change an existing target's HP, speed, position, or alive state. |
| `step(n=1, direction=(0,0), full=False, validate=False)` | Advance fixed ticks, optionally returning full actors or checking invariants. |
| `snapshot(full=True)` | Inspect the actual native world. `full=False` omits actor arrays. |
| `enemy(handle)` | Inspect one enemy, or return `None` when it no longer exists. |
| `catalog()` | Read definitions, evolutions, and native per-rank/evolved weapon specifications. |
| `invariants()` | Assert finite state, grid alignment, unique handles, and bounded actor pools. |
| `pause()`, `choose(i)`, `reroll()`, `banish(i)`, `grant_xp(n)` | Drive progression through normal game entry points. |
| `capture(path, **options)` | Ask the native host to render/capture the real scene; unavailable in the headless host. |
| `benchmark(ticks=600, warmup=120)` | Return native simulation timing samples after warmup. |
| `wait_until(predicate, ticks, chunk=1, message=..., state=...)` | Bounded exact-tick polling with useful failure context. |
| `clear(owned=True)` | Clear actors/effects, optionally retaining equipment. |

Player fields include `position`, `previous`, `direction`, `segments`,
`previous_segments`, `move_clock`, `move_interval`, `hp`, `max_hp`, `level`, `xp`,
`next_xp`, `length`, and `invulnerable`. Enemy kinds are
`red`, `splitter`, `swift`, and `boss`; fixture enemies also accept `radius`,
`length`, and `direction`.

Enemy fixtures accept HP up to `1e12` so dense performance tests can retain
their target population after evolution tuning. This changes test placement
limits; the ordinary enemy director still authors gameplay HP.

Fixture enemy handles occupy `1000000000..4294967295`, separate from the normal
director's IDs. `spawn_enemy(..., id=1000000000)` can request a specific unused
handle in that range; automatic handles skip occupied fixture IDs. Lower IDs,
duplicates, and non-integer IDs are rejected without consuming a handle.

## State and profiling

Snapshots always contain `grey_system` (scheduled spawning, clock, next spawn),
and `counts.grey_snakes`, `counts.grey_trails`, `counts.grey_barriers` (living
heads, retired trails, distinct occupied cells). Full snapshots include
`grey_trails` with every oldest-first path and its actual AI/movement state.
Reset and clear remove all grey barriers; isolated resets disable grey spawning.

Snapshots always contain `phase`, `tick`, `elapsed`, `seed`, `player`, `owned`,
`stats`, `counts`, `events`, `shield`, `orbit_phase`, `ouroboros_active`, `cobra_overflow`, `leviathan`, `offers`, and
`timing`, `notice`, `notice_time`, and `chest_rewards`. Full snapshots also contain `enemies`, `projectiles`, `zones`,
`nest_eggs`, `mini_snakes`, `beams`, `cobra_pits`, `cobras`, `grapples`, and
`pickups`, `orbit_fangs`, and `orbit_fang_states`. Snake paths include both current and previous grid waypoints.

`player.collision_clock` is read-only: negative when clear, otherwise simulation
seconds since a blocked body/wall/grey move began its one-second grace period. Pause
freezes it, a safe step cancels it, and fixture relocation clears it.

`chest_rewards` is a durable ordered ledger of the last 32 opened chest rewards,
not a one-tick event. Entries contain `serial`, `kind` (`upgrade`, `evolution`, or
`treasure`), upgrade `id`/`definition`, resulting `rank`, actual `gold`/`healing`,
and display `title`/`description`. Rewards have already been applied when their
records appear. `reset()` clears the ledger and chest counter; `clear()` clears
the ledger with other fixture presentation state while retaining counters.

Owned weapons include `spec`: the actual native resolved damage, cooldown,
range, area, speed, lifetime, tick interval, projectile count, piercing,
ricochets, brood count, and persistence flags. Tests can compare these source
contracts and then independently observe actor creation, targeting, contact,
lifecycle, and damage behavior.

Timing fields are `mean_us`, `p50_us`, `p95_us`, `p99_us`, `max_us`, `total_us`,
and `ticks`. They time `Game::update` plus automatic level choice, excluding JSON
serialization, rendering, subprocess I/O, and Python assertions. Native render
timing is reported separately by `snake_render_benchmark`. Do not describe
headless update timings as full-game FPS.

## Wire protocol

The executable reads one JSON object per line from stdin and writes one response
per line to stdout. Native logging goes elsewhere. Every Python request has a
`request_id`; the host echoes it. Examples:

```json
{"cmd":"reset","seed":55,"isolated":true,"request_id":1}
{"cmd":"equip","id":"venom_shot","rank":8,"evolved":false,"request_id":2}
{"cmd":"step","ticks":120,"full":true,"request_id":3}
```

Successful responses are `{"ok":true,"request_id":N,"result":...}`. Errors are
`{"ok":false,"request_id":N,"error":{"type":...,"message":...}}`. Malformed
JSON and unsupported commands report errors while leaving the process usable.
Requests are bounded to 4 MiB, enemy storage to 1,800, and a single step request
to 120,000 ticks. `quit` closes the session. The Python client raises exceptions
on host errors, non-JSON output, mismatched responses, timeouts, or process exit.

Native command errors leave a session usable. Transport failures (including a
timeout) close it immediately so a late reply cannot be mistaken for the next
command's response. `game.closed` reports this state. The runner starts a fresh
host with the same executable, native/headless mode, and data directory before
the next independent test; the failed test still records its original failure.

The API is a developer test interface; ordinary gameplay does not listen for
commands or spawn Python.
